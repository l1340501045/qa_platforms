# QA 平台 UI/UX 重构与主流程安全对齐 PRD

## 目标

把当前 QA 智能测试平台从“能跑流程的管理后台”升级为“QA 工程师日常可用的自动化测试工作台”：

- 具备 QA 背景、但首次使用本平台的人能按自然动线完成：建系统 -> 上传/管理需求资料 -> 触发生成 -> 处理澄清/失败 -> 审查用例 -> 沉淀用例库 -> 搜索/导出。
- 页面信息架构、交互、视觉层级、加载/空态/错误态符合企业后台和测试管理工具的常见最佳实践。
- 修复已确认的 UI/UX 和展示数据缺陷，但不改变后端测试用例生成核心逻辑。
- 在大改前保护当前 `feat/architecture-migration` 阶段性成果，先完成脏工作区盘点与提交/合并策略，再从该分支的干净 checkpoint 拉出 UI/UX 重构分支；`main` 只作为最终集成目标，不作为本次 UI/UX 直接开发分支。
- 每次 Trellis 流程产出都必须做批判性 review：先指出可能偏离目标、过度设计、遗漏主流程保护或证据不足的地方，再决定是否进入下一阶段。

## 背景与已确认事实

### 用户观察到的问题

- 系统列表页中 `漫剧批创系统` 显示文档数/批次数为 0，但实际存在文档和批次。
- 知识库上传入口没有让用户选择文档类型，上传后文档类型显示为 `other`。
- 批次用例树页面默认展开所有目录，且树区域没有合理高度/滚动/搜索，目录多时需要滑很久才能操作下面的文件夹。
- 当前 UI/UX 看起来偏旧，具备 QA 背景的人首次使用本平台时动线不清晰。
- 当前还有多个阶段性分支和大量未提交改动，需要先判断哪些成果固化到 `feat/architecture-migration` checkpoint，哪些不进，最终希望 `main` 是其他人可直接部署使用的纯净项目。

### 代码与数据证据

- 当前 API 和前端开发服务未运行：`127.0.0.1:3000` 与 `127.0.0.1:8000/health` 均连接失败；Docker 基础设施 Postgres/Redis/MinIO 仍在运行。
- 本地 DB 只读查询确认 `漫剧批创系统` 实际存在 `document_count=1`、`batch_count=3`，截图中的 0 不是数据真实为 0。
- 系统卡片前端读取 `system.document_count ?? 0` 和 `system.batch_count ?? 0`，见 `web/src/pages/Systems/index.tsx:135`。
- 后端 `SystemService.list_systems` 只返回 `public.systems` 行和总数，没有聚合文档/批次数，见 `src/platform_api/services/system_service.py:42`。
- 上传接口后端已支持 `doc_type` query 参数，但默认值为 `other`，见 `src/platform_api/api/v1/documents.py:56`。
- 前端上传 service 只提交 `files`，没有传 `doc_type`，见 `web/src/services/documentApi.ts:28`。
- 知识库页上传 UI 没有文档类型选择控件，见 `web/src/pages/Knowledge/index.tsx:213`。
- 知识库文档树使用 `Tree defaultExpandAll`，见 `web/src/pages/Knowledge/index.tsx:251`。
- 工作台用例树使用 `Tree defaultExpandAll`，见 `web/src/components/CaseTreeReview.tsx:488`。
- 用例库用例树使用 `Tree defaultExpandAll`，见 `web/src/pages/CaseLibrary/index.tsx:570`。
- 工作台和用例库重复实现树构建、节点解析、标签颜色、可信度展示等逻辑，见 `web/src/components/CaseTreeReview.tsx:207` 与 `web/src/pages/CaseLibrary/index.tsx:194`。
- 当前后端用例树契约是 `Document -> modules[] -> branches[] -> cases[]`，分支层被聚合为列表，不是通用递归树，见 `src/platform_api/services/case_tree_service.py:37`、`src/platform_api/services/case_tree_service.py:153`。
- 当前工作区很脏，`git status --short` 显示大量已修改和未跟踪文件，覆盖生成质量、模块树、平台 API、前端页面、Docker/Trellis 基建等。
- 当前分支为 `feat/architecture-migration`；本任务采用 stacked branch 策略，UI/UX 大改不得直接混入当前脏工作区，也不得直接在 `main` 上开发。

## 行业/最佳实践基准

详见 `research/industry-ux-benchmark.md`。本任务采用以下基准原则：

- 可见系统状态、匹配真实世界、用户控制、错误预防、识别优先于回忆、审美与极简，是企业后台和复杂工具的基础可用性要求。
- 数据密集型后台应优先使用可扫描的信息架构、筛选、搜索、分层导航、稳定表格布局、明确状态和批量操作，而不是大面积装饰型页面。
- 树形控件用于层级导航时，应默认控制展开深度，提供搜索/过滤/定位，支持键盘与可访问性，并避免无限撑高页面。
- 大表格/大树需要固定容器、分页或虚拟滚动，避免把导航和主体内容互相拖垮。
- 测试管理工具的核心资产不是“页面”，而是需求/模块/用例/执行/审查/导出的可追溯工作流。

## 范围

### 必做

1. 脏工作区与分支治理
   - 盘点当前所有未提交改动，按来源和业务价值分组。
   - 明确哪些属于阶段性成果，应先固化到 `feat/architecture-migration` checkpoint；哪些属于本次 UI/UX 才处理；哪些是临时/运行产物应忽略或清理。
   - 在 UI/UX 重构开始前，给出可执行提交计划，不允许 `git add .`。
   - UI/UX 重构必须从 `feat/architecture-migration` 的干净 checkpoint 新拉分支，建议分支名 `feat/qa-platform-ux-modernization`。

2. 主流程安全红线
   - 不改变测试用例生成 pipeline 的核心后端逻辑、LLM 调用策略、case 生成/核验算法。
   - 不破坏“上传文档 -> 触发生成 -> worker 执行 -> 进入审查 -> 审查/迭代/落库/导出”的完整通路。
   - 所有 UI 改动必须能在 API/worker 不可用、批次失败、批次运行中、待澄清、待审查、已归档等状态下给出清晰反馈。

3. 系统列表与首页动线
   - 系统列表必须显示准确的文档数、批次数和关键状态，不能用缺字段默认为 0 掩盖数据缺失。
   - 系统卡片/列表应让 QA 快速判断哪个系统可继续工作：最近批次、最近更新时间、待审/失败/运行中状态。
   - 入口动线从“系统管理”调整为更贴近 QA 工作流的“工作台/项目/知识库/用例资产/审查/导出”。

4. 文档上传与知识库体验
   - 上传前必须能选择文档类型；默认推荐 `prd`，但用户可选 `tech_doc/test_rule/prototype/other` 等。
   - 单个上传请求中的文档类型必须传到后端并在列表中准确展示。
   - 上传区要区分主 PRD、技术文档、测试规则、原型/图片资产的用途，避免首次使用者把所有资料都变成 `other`。
   - 文档树默认不全展开，树区域有最大高度、内部滚动、搜索/过滤、节点数量提示和“展开/收起全部”操作。

5. 用例工作台与用例库
   - 树形导航默认只展开到 1-2 层或恢复用户上次展开状态，不能默认全展开全部模块。
   - 树区域固定宽度和最大高度，内部滚动；主体用例表独立滚动/分页。
   - 提供模块/分支搜索、只看 P0、只看待审、只看待澄清/待修正、只看稳定主集等快捷筛选。
   - 用例树要能表达“模块 -> 子分支树 -> 用例”的层级，不再把复杂路径只铺成一层分支列表。
   - 工作台和用例库共用同一个用例资产浏览组件/工具函数，避免两处重复实现继续漂移。
   - 保留短步骤用例，不以“步骤少”作为质量问题；质量判断以断言明确、预期可验证、来源可追溯为准。

6. 视觉与交互系统
   - 基于现有 React 18 + Ant Design 5 + Zustand + axios 技术栈，不引入重型 UI 框架。
   - 建立轻量设计 token/布局组件：导航、页面头、筛选条、统计摘要、树表布局、状态标签、空态/错误态。
   - 页面以工作效率为核心，保持密度适中、信息可扫描、按钮含义明确、状态颜色一致。
   - 支持常见桌面宽度和较窄屏，不出现文字溢出、控件互相遮挡、树/表撑破页面。

7. 验证
   - 补充后端聚合统计和上传 `doc_type` 的单元/接口测试。
   - 补充前端组件测试或 Playwright 冒烟，覆盖上传文档类型、系统统计展示、树默认折叠/搜索/滚动、工作台主流程入口。
   - 起本地前端/API/worker 后，用浏览器或 Playwright 截图验收核心页面。
   - 每个阶段完成后输出批判性 review，至少回答：
     - 是否更接近 QA 工程师真实工作流，而不是只修了局部样式。
     - 是否误伤或弱化完整生成测试用例主流程。
     - 是否引入重复实现、过度抽象或难以回滚的大改。
     - 验证证据是否足以支撑完成结论。

### 不做

- 不重写测试用例生成算法。
- 不调整 LLM 网关、模型、并发、pipeline 质量策略。
- 不做完整权限/登录系统；当前项目无鉴权层，这是独立任务。
- 不做移动端优先设计；目标是桌面 QA 工作台，但窄屏不能明显破版。
- 不把当前 `.audit/`、`logs/`、运行缓存等临时产物直接提交到 `feat/architecture-migration` 或 UI/UX 分支，除非用户明确确认其作为工具链资产进入仓库。

## 验收标准

- `feat/architecture-migration` checkpoint 状态清晰：当前阶段性成果已按用户确认的提交计划保留，UI/UX 分支从该干净基线创建；最终合入 `main` 的路径单独可审。
- 系统列表中 `漫剧批创系统` 不再显示文档数/批次数为 0；后端接口返回聚合字段，前端不再依赖缺字段兜底造成假 0。
- 上传 PRD 时，前端可选择文档类型，接口请求带 `doc_type`，上传后的文档列表显示所选类型。
- 知识库、工作台、用例库的树控件默认不全展开；树区域有最大高度/滚动，并可搜索或快速定位节点。
- 用例树支持模块下的多级分支表达；模块和分支结构不再被强行一层平铺。
- QA 能从一个系统进入知识库、选择文档、触发生成、处理澄清、审查用例、查看用例库、导出，不遇到阻断性 UI 回归。
- 前端 lint/type-check 通过；涉及后端的测试通过；核心页面 Playwright/浏览器截图验收通过。
- 任务报告中列出主流程保护结果：未改动的生成核心文件、改动过的 API/前端边界、验证命令和截图/接口证据。
- 每个子任务有独立 review 记录；父任务最终报告必须汇总这些 review 的结论和未解决风险。

## 开放决策

当前不阻塞规划，但实施前需要用户确认：

- 分支治理决策：当前 `feat/architecture-migration` 的哪些阶段性成果固化为 UI/UX 基线，哪些暂不进入基线，最终何时再合入 `main`。
- UI/UX 分阶段策略：建议先做“主流程可用性与关键 bug 修复 + 树表工作台重构”，再做更彻底的视觉 polish；如果一次性全量重构，风险更高、审查周期更长。
