# 全局布局窄屏导航可用性

## Goal

让 QA 工程师在窄屏、分屏、打开 DevTools 或较小笔记本窗口时，仍能清晰进入平台核心页面：工作台、项目/系统、用例资产、全局搜索、导出中心。

这只优化前端全局壳层，不改变任何后端接口、生成配置、worker、pipeline 或 testcase generator 逻辑。

## Background

当前 `MainLayout` 使用固定左侧栏。桌面宽度下可用，但在窄屏场景会长期占用横向空间，使主内容被挤压，数据表格和主流程动作更容易落入横向滚动深处。

对 QA 工作台来说，导航不是装饰：它是“从待办批次 -> 项目资料 -> 用例资产 -> 搜索 -> 导出交付”的工作流入口。窄屏下导航必须仍可达，但不能牺牲主内容可操作面积。

## Requirements

1. 桌面宽度继续使用现有左侧栏导航，保持当前视觉和路由高亮规则。
2. 窄屏时隐藏固定侧边栏，改为顶部菜单按钮打开抽屉导航。
3. 抽屉导航必须包含与桌面侧边栏一致的菜单项、图标、顺序和当前路由高亮。
4. 点击抽屉菜单项后必须导航到对应路由，并关闭抽屉。
5. 顶栏必须保留当前页面标题、副标题和通知入口；窄屏下标题不能被菜单按钮或通知遮挡。
6. 主要内容区在窄屏下不能再被固定侧边栏挤压；页面级布局不应新增横向滚动。
7. 不改变首页默认路由 `/ -> /review`，因为当前前端规范明确首页默认跳转工作台。
8. 不改变业务页面内部的数据加载、筛选、生成、审查、导出逻辑。

## Acceptance Criteria

- [ ] 桌面下左侧栏仍显示，菜单顺序为：工作台、项目/系统、用例资产、全局搜索、导出中心。
- [ ] 窄屏下左侧栏不占宽度，顶部出现可访问的菜单按钮。
- [ ] 抽屉打开后显示同一套菜单，并高亮当前页面。
- [ ] 抽屉菜单点击后完成导航并关闭抽屉。
- [ ] `/batches/:batchId` 仍高亮工作台；`/systems/:systemId/documents` 与 `/documents/:documentId` 仍高亮项目/系统。
- [ ] 顶栏标题和通知入口在窄屏下不重叠。
- [ ] 前端 lint、build、现有 UI 模型测试通过。

## Out of Scope

- 不重新设计整套视觉主题。
- 不新增移动端底部导航。
- 不改变导航顺序、首页默认落点或已有路由。
- 不改后端、不改真实生成链路。

## Planning Review

这个任务对齐父任务方向：它改善“首次使用平台也知道入口在哪里”的基础体验，并且遵守主流程安全约束。关键风险是全局壳层影响所有页面，所以实现必须保持桌面行为稳定，只在窄屏切换导航呈现方式。
