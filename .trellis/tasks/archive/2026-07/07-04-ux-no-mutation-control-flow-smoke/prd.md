# UI无副作用控件动线巡检

## Goal

在不上传文件、不创建批次、不触发 LLM、不提交任何 mutation 的前提下，验证 UI/UX 分支中几个关键控件是否真的支撑 QA 第一次使用平台时的自然动线：

- 知识库上传前能看懂并选择文档类型。
- 全局搜索能从业务关键词定位历史用例，并能追溯回来源批次。
- 导出中心能看懂导出入口和范围选择，但不实际创建导出任务。
- 批次/资产树的搜索、展开、收起控件可见且不会把页面撑爆。

本任务用于补强页面交互证据，不替代真实小批次跑批、首次使用平台 QA 演练或 `.audit` 审查。

## Requirements

- R1：只执行无副作用操作；允许打开弹窗、打开下拉、输入搜索关键词、清空搜索，但禁止点击会上传、生成、删除、确认、落库、创建导出的最终提交按钮。
- R2：优先用真实本地页面和现有数据巡检，记录页面状态、控件文案和发现的问题。
- R3：至少覆盖知识库文档类型选择、全局搜索、导出中心新建导出弹窗、批次工作台树控件、用例资产树控件。
- R4：记录浏览器 console warning/error、页面横向溢出和是否出现持续 loading。
- R5：不得修改平台运行代码，不得修改 `src/testcase_generator/**`。
- R6：产物必须包含批判性 review，明确本轮证据边界。

## Acceptance Criteria

- [x] 知识库上传类型控件可见，默认值和可选项有记录。
- [x] 搜索关键词能得到结果，且结果中存在可追溯来源批次入口。
- [x] 导出新建弹窗可打开并看懂范围/格式入口，但没有创建新导出任务。
- [x] 批次工作台和用例资产树控件可见，搜索/展开/收起入口有记录。
- [x] 报告明确本轮没有触发 LLM、没有上传、没有创建批次、没有创建导出。
- [x] `src/testcase_generator/**` 无 diff。
