# UI 无副作用控件动线巡检自审

## 结论

本轮巡检补强了“页面能打开”之外的交互证据：关键控件不只是存在，而且文案和入口能支撑 QA 的自然动作。它没有发现新的 P0/P1 UI 阻断。

## 批判性问题

### 1. 是否更接近 QA 工程师真实工作流

是，但仍是有限接近。验证范围覆盖了上传前资料类型判断、历史断言搜索、回到来源批次、资产页回到工作台、导出范围选择。它们都是 QA 日常自动化测试资产流转中的关键动作。

不足是没有真实上传、生成和导出，所以不能证明“完整任务已经完成”，只能证明控件层没有明显迷路点。

### 2. 是否误伤完整生成主流程

没有。巡检没有触发生成，也没有改 `src/testcase_generator/**`。所有操作都是只读或打开/关闭弹窗。

但也因此没有验证 worker 真实生成和后端 mutation 的完整路径。

### 3. 是否存在过度解释

需要克制。搜索能回到旧批次，不等于新批次模块树一定正确；导出弹窗说明清楚，不等于导出文件一定正确；上传类型默认 PRD，不等于真实上传后一定入库为 PRD。

所以报告只把结论限定为“可以继续真实验收”，不写“可以合 main”。

### 4. 是否有新的 UX 风险

没有发现阻断性风险。一个细节是导出弹窗取消后 DOM 中仍保留隐藏 modal 节点，这是 Ant Design 常见实现，不是可见 UI 问题；确认导出任务总数未变化即可。

### 5. 是否改变父任务结论

不改变。父任务仍缺：

- 当前 HEAD 新小规模真实批次。
- 具备 QA 背景但首次使用平台的人的任务演练。
- 新批次 `.audit/<batch_id>/` 审查。

## 判定

可以收口为“无副作用控件动线巡检证据”。它应该进入父任务证据矩阵，但不能作为 GO 合并依据。
