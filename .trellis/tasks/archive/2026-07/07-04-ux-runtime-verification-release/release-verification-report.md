### 文档类型上传

结果：

结论：新上传路径已经支持文档类型，不会再把前端上传的新文件默认落成 `other`。

残余问题：历史文档仍是 `other`，本次没有做数据迁移或自动回填。

### 临时数据清理

探针清理时发现：删除临时文档后再删除临时系统仍返回 409。原因是文档服务软删除后，系统删除仍按关联存在判断，软删除文档仍会阻止系统删除。

本次为了保持环境干净，对该临时系统和临时文档做了精确硬清理：

- 删除文档 ID：`126cc4fe-b036-4fce-9032-780afe6317c0`。
- 清理后系统不存在。
- 清理后该系统文档数为 0。

这是后端清理语义问题，不影响正常生成主流程，但影响测试数据清理和运维体验。

## 问题清单

### P1: 前端 lint 门禁缺失

`npm run lint` 失败原因是缺少 ESLint 配置文件。当前不是代码语法错误，而是工程门禁没有建完整。若 main 分支目标是“别人 git 部署即可使用并能跑基本质量检查”，应补 ESLint TypeScript/React 配置和依赖。

### P1: 系统删除与文档软删除语义不一致

删除文档后系统仍因软删除记录返回 409，导致 UI/API 层很难干净清理临时系统。建议后续统一删除语义：系统删除检查应忽略软删除文档，或提供明确的级联/归档删除能力。

### P2: 历史文档类型仍为 `other`

新上传已正确支持 `prd`，但旧文档仍显示 `other`。这会让 QA 在文档详情里误判资料类型。可做一次性迁移、人工改类型入口，或在详情页给历史 `other` 提示“可重新标注”。

### P2: 项目/系统默认排序仍不够贴近当前工作

系统页统计真实，但目标业务系统不一定出现在最显眼位置。对首次使用平台的人来说，默认列表应更偏向最近活动、待处理或有批次的系统，并提供搜索/筛选。

### P2: 窄屏下表格信息仍偏密

1024 宽度无页面级横向溢出，但用例资产和批次表的状态/操作列比较紧。桌面主场景可接受，后续可通过固定操作列、列密度配置或详情优先布局改善。

### P3: 构建产物 chunk 偏大

Vite build 通过，但提示主 chunk 超过 500 kB。当前不阻塞主流程，后续可做路由级拆包或按页面懒加载。
