# UI 验收前预检脚本自审

## 结论

这次新增的 `scripts/ux_acceptance_preflight.py` 是合理的验收辅助工具。它把周一真实跑批前最容易漏掉的分支、工作区、生成核心 diff、验收资料、模型配置和服务健康检查集中到一个只读命令里，能降低误跑批的概率。

## 价值

- 提前发现不在目标分支、工作区不干净、`.env` 模型配置不对这类低级但代价很高的问题。
- 明确检查 `src/testcase_generator/**` 相对 checkpoint 无 diff，继续保护“UI/UX 分支不混生成核心逻辑”的边界。
- 运行态检查失败时给出中文处理建议，适合用户回公司后按提示处理。
- `--skip-runtime` 允许先做静态检查，不要求服务已经启动。

## 风险和边界

- preflight 不能证明真实 LLM 批次会成功；它只证明跑批前的本机状态更像 runbook 目标状态。
- preflight 不能替代首次使用平台的 QA 任务演练；人的理解成本仍要真实观察。
- preflight 检查 `.env` 的模型配置是硬编码对齐当前 runbook。后续如果模型策略调整，需要同步脚本和文档。
- runtime 检查只能证明 API / frontend / worker 有响应，不能证明上传、生成、审查、导出整条主链路都可用。

## 是否偏离目标

没有。脚本不改后端业务逻辑、不写数据库、不触发生成，只是降低真实 UI/UX 验收前的操作风险。它让“周一跑真实批次并回填审查”更稳，但不会把父任务误判为已完成。
