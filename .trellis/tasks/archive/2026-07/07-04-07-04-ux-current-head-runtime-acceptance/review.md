## 风险判断

当前最大风险不是“页面打不开”，而是“真实业务链路还没在最新代码下重新跑一遍”。

因此下一步应该优先跑真实小批次，而不是继续堆 UI 微调。只有真实新批次能同时验证：

- 上传/生成入口是否真的可用。
- LLM 网关与 worker 是否稳定。
- 新批次在工作台和资产页的展示是否正常。
- 搜索和导出是否能吃到新沉淀的数据。

## 后续建议

合 main 前建议至少补一轮：

1. 公司网络下小规模真实 LLM 批次。
2. 基于新批次的审查、落库、搜索、导出链路。
3. 一个未参与开发的 QA 首次使用任务脚本。

通过后再进入 PR / main 合并准备。
