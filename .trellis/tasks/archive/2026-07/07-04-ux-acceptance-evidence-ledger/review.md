# UI 验收证据台账自审

## 结论

这份台账是必要的。当前 UI/UX 父任务已经有很多文档和 dry-run 证据，但真正能支持合 main 的硬证据仍来自周一真实小批次、首次使用平台 QA 演练和新 `.audit` 审查。台账把“已有材料”和“未完成证据”分开，降低误判风险。

## 自审问题

### 1. 是否把流程搞复杂了

有轻微增加阅读入口的风险，但可接受。`runbook.md` 仍是唯一操作流程，`evidence-ledger.md` 只是判定总账；README 也写明它不替代 runbook。

### 2. 是否把未完成证据包装成完成

没有。台账明确当前结论仍是“候选交付，可以进入真实小批次验收，但不能直接合 main”，并把小批次、真人演练、`.audit` 审查全部标为未完成。

### 3. 是否偏离主目标

没有。用户的目标不是多写文档，而是保证 UI/UX 重构真正符合 QA 首次使用动线且不影响主流程。证据台账直接服务这个目标：后续 Codex review 会按台账拿证据，不靠印象。

### 4. 是否影响主流程

不影响。本次只修改 `docs/acceptance/**` 和 Trellis 任务文档，没有修改前端、API、worker 或 `src/testcase_generator/**`。

## 判定

可以收口。下一步仍然是周一按 runbook 跑小规模真实批次，并把 evidence ledger 中的未完成项逐项补齐。
