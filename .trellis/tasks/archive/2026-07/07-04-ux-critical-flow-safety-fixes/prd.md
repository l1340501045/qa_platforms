# 阶段 B：主流程安全 UX 快修 PRD

## 目标

在不改变生成核心逻辑的前提下，先修复已证实且阻碍 QA 日常使用的低风险问题：系统统计假 0、上传文档类型缺失、树默认全展开和树区域不可控。

## 前置依赖

必须先完成或由用户明确放行阶段 A：`.trellis/tasks/07-04-ux-branch-hygiene`。

## 必做

- 系统列表 API 返回真实 `document_count` 和 `batch_count`，前端不再把缺字段静默显示为 0。
- 上传文档前可选择 `doc_type`，默认推荐 `prd`，请求必须携带类型。
- 后端校验 `doc_type` 合法性。
- 知识库、工作台、用例库的树默认不全展开。
- 树区域有固定高度/最大高度和内部滚动。
- 提供展开全部、收起全部、搜索/过滤或等价定位能力。
- 保持完整生成测试用例主流程可用。

## 不做

- 不重构整体导航和视觉系统。
- 不抽用例资产共享组件。
- 不改变 `src/testcase_generator` 生成核心逻辑。

## 验收

- DB 中 `漫剧批创系统` 有 1 个文档、3 个批次时，系统列表不显示 0/0。
- 上传 `.md` 选择 `prd` 后，列表展示 PRD 类型。
- 旧批次大树页面打开后不再默认全展开，树自身滚动，不撑长页面。
- 相关后端测试、前端 lint/type-check 或最小构建通过。
