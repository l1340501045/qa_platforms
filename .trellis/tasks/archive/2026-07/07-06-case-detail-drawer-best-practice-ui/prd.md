# 用例详情抽屉最佳实践与 UI 优化

## Goal

优化用例详情抽屉的信息架构和视觉呈现，使 QA 查看单条用例时能清楚区分“每步预期”和“整条用例通过标准”，并让测试步骤区域更像可执行测试脚本，而不是灰色备注。

本任务应保持现有后端数据结构和 API 契约不变，仅在前端展示层调整字段命名、布局和视觉层级。

## Background

- 用户反馈当前抽屉中“测试步骤”内已有“预期结果”，底部又展示“预期结果”，语义重复，不符合常见测试用例结构。
- 行业通用测试用例结构通常包含前置条件、测试步骤、输入/测试数据、每步预期结果、实际结果/通过判定等字段；BDD 的 Given-When-Then 也强调前置状态、动作、结果应边界清晰。
- 当前仓库既有数据模型已支持：
  - `preconditions`：前置条件。
  - `steps[].action`：步骤动作。
  - `steps[].input_data`：步骤输入数据。
  - `steps[].expected_result`：每步预期结果。
  - `expected_results`：整条用例的预期结果汇总。
- 因此对齐最佳实践不需要改后端结构，可以将 `expected_results` 在前端展示为“通过标准”或“断言汇总”，继续沿用原字段保存。

## Requirements

- R1：阅读态中，测试步骤区域必须突出“步骤动作”和“步骤预期”，避免继续使用 Ant Design `Steps` 默认灰色 description 样式导致内容像备注。
- R2：阅读态中，底部 `expected_results` 不再展示为“预期结果”，应改为“通过标准”，表达整条用例最终判定标准。
- R3：阅读态中，步骤内预期结果继续保留，语义为“每步执行后的可观察结果”。
- R4：编辑态中，`expected_results` 字段的用户可见文案同步改为“通过标准”，但提交给后端的字段名仍为 `expected_results`。
- R5：不得修改后端数据库结构、Pydantic schema、接口字段名或现有批次/用例生成链路。
- R6：视觉风格应沿用当前 React + Ant Design 5 后台风格，保持信息密度、清晰层级和可扫描性，不做营销式装饰。

## Acceptance Criteria

- [ ] 查看用例抽屉中，“测试步骤”不再呈现为整块灰色弱化说明，步骤动作、输入数据、步骤预期均清晰可读。
- [ ] 查看用例抽屉中，底部汇总区标题为“通过标准”，不再与步骤内“预期结果/步骤预期”混淆。
- [ ] 编辑用例时，原 `expected_results` 编辑区域显示为“通过标准”，保存请求仍使用原 `expected_results` 字段。
- [ ] 前端构建或类型检查通过。
- [ ] 变更范围仅限前端展示层和 Trellis 任务/规范文档，不包含后端数据结构迁移。

## Out Of Scope

- 不新增实际结果录入、执行记录、测试运行状态等测试执行管理能力。
- 不调整用例生成 prompt 或后端生成出的 JSON 字段结构。
- 不重构整套抽屉组件或引入新的 UI 组件库。
