# 真实跑批用例质量复审

## Goal

对最新真实跑批 `5ad9f447-4502-447e-8c8a-cd818e370248` 的 2660 条用例做结构化质量复审，判断这批用例是否已经达到“QA 可以进入人工审核/局部修复”的状态，并把剩余问题拆成可行动的根因与后续任务建议。

本任务只做只读审查和报告记录，不修改生成逻辑、不修改用例审核状态、不触发新跑批。

## Requirements

- R1：审查对象必须是当前 API 返回的最新批次 `5ad9f447-4502-447e-8c8a-cd818e370248`，系统为“漫剧批创系统”，文档为“漫剧批创初版功能PRD”。
- R2：审查必须使用真实数据库/API 产物，不凭旧报告或截图下结论；如果服务不可访问，必须记录阻塞原因。
- R3：沿用 `.audit/` 目录下的模块切片审查思路：先按模块/分支/质量桶生成审查素材，再按风险分层抽样复核，最后汇总总报告。
- R4：必须覆盖全局统计、模块树归类、质量桶分布、待澄清/需修复样本、重复/灌水风险、步骤与断言质量、PRD 接地性。
- R5：必须区分“UI 展示问题”“生成策略问题”“PRD 信息缺口”“人工审核可接受的短步骤用例”，不得为了形式强行要求每条用例多步骤。
- R6：不得上传文档、触发生成、确认/删除/修改用例、创建导出任务或写入业务数据库。
- R7：报告必须包含可复现的数据来源、抽样方法、关键发现、严重程度、根因、行业最佳实践对齐建议、是否建议进入下一轮真实跑批。
- R8：不得修改 `src/testcase_generator/**`；如发现生成侧问题，只记录到报告和后续任务建议。
