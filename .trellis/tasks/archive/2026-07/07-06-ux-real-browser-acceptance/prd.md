# UI真实浏览器验收

## Goal

在不修改业务代码和不触发新跑批的前提下，启动当前分支的 API / 前端，用真实数据库中的最新漫剧批创批次做浏览器验收，判断当前 UI/UX 分支是否满足 QA 工程师首次使用平台时的关键工作动线：

- 能从工作台识别待处理批次并进入批次页。
- 能在批次页理解批次状态、模块树、用例表、质量桶和下一步动作。
- 能在用例资产页按业务模块/分支定位用例，不被默认全展开或错误空态误导。
- 能在知识库/文档/导出中心看到主流程入口和交付出口。
- 能明确区分 UI/UX 问题与生成侧用例质量债务，不把生成债务误判为前端阻塞。

## Requirements

- R1：验收必须在当前分支 `feat/qa-platform-ux-modernization` 上进行，并保留当前导出相关脏工作区，不提交、不回滚、不混入本任务。
- R2：启动或确认 API 与前端服务可用；优先使用当前工作区代码运行，不使用旧镜像。
- R3：只读访问真实数据；不得上传新文档、不得触发生成、不得修改用例审核状态、不得创建导出任务。
- R4：至少浏览 `/review`、最新批次 `/batches/5ad9f447-4502-447e-8c8a-cd818e370248`、`/case-library`、`/systems/6b0ea53c-f734-4bc9-8506-663d47107b9d/documents`、`/exports`。
- R5：重点验证 QA 首次使用平台时是否能知道“现在该干嘛”：入口、状态、主动作、返回路径、空态/错误态、待处理债务都必须清楚。
- R6：重点验证批次页模块树是否默认可控、不会全展开拖长页面；选中模块/分支后右侧用例列表可读可操作。
- R7：重点验证主集候选、待澄清、需修复等质量状态没有被 UI 文案包装成“已确认可交付资产”。
- R8：验收报告必须包含截图或浏览器观察证据、发现的问题、严重程度、根因归类、是否阻塞父任务合并。
- R9：产物必须包含批判性自审，说明证据边界，尤其说明哪些结论来自浏览器观察，哪些只来自数据库/审查包。
- R10：不得修改 `src/testcase_generator/**`；本任务原则上不改运行代码，只记录验收报告。

## Acceptance Criteria

- [x] API 与前端服务可访问，或明确记录无法访问的具体阻塞原因。
- [x] 至少完成 5 个目标路由的真实浏览器验收记录。
- [x] 报告给出 GO / FIX THEN GO / NO-GO / SPLIT OUT 判定。
- [x] 报告区分 UI/UX 阻塞项与生成侧质量债务。
- [x] `src/testcase_generator/**` 无 diff。
- [x] 当前导出相关脏改动未被本任务提交或回滚。
