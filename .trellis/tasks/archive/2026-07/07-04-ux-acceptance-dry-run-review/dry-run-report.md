## 观察到的 follow-up

### 1. 待审批次页“落库归档”按钮可用

批次页处于“待审阅”状态时，页面同时显示：

- `待审 1`
- `落库归档` 按钮可用
- 辅助文案：“没有需修改用例时，可将当前批次落库归档。”

这不一定是 bug，因为当前规则可能允许未标记需修改时直接归档；但首次使用平台的 QA 可能会误以为“不用确认每条也能归档”。真实验收时应重点观察 TA 是否理解“确认 / 需修改 / 删除 / 落库归档”的关系。

建议暂不作为合并阻塞，除非真人演练中出现误操作倾向。

### 2. 用例资产页默认选中系统可能没有资产

`/case-library` 当前默认选中 `test_sys_145f29f9`，视图为空，但空态提供“上传/生成”入口。这个空态是可理解的，不过真实小批次完成后仍需验证新批次资产能在这里被定位。

## 对 runbook 的影响

当前 `docs/acceptance/runbook.md` 与页面基本一致：

- 首页默认工作台，符合“判断首页是否能进入工作台或项目/系统”。
- 项目/系统能进入知识库。
- 知识库上传前可选资料类型，且显示本次上传类型。
- 生成弹窗明确会创建批次并进入工作台。
- 批次页能看到阶段进度、状态、模块树和审查动作。
- 用例资产、搜索、导出入口存在。

本轮没有发现必须修改 runbook 的不一致。
