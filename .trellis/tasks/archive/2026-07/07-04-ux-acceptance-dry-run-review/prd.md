# UI验收前页面动线dry-run复查

## 目标

在不触发真实 LLM 生成的前提下，用当前运行态页面复查首次使用入口、导航、文案和验收 runbook 是否一致，补充 dry-run 报告。

## 背景

真实小规模批次还需要公司 LLM 网关。当前本机 API / frontend / worker 已通过 preflight，可以先做不触发生成的页面 dry-run，提前发现：

- runbook 步骤与真实页面入口不一致。
- 首次使用平台的 QA 可能卡在首页、项目/系统、知识库、上传区域、批次页、用例资产、搜索、导出入口。
- 当前页面有明显布局、文案、状态或导航问题，但不依赖真实 LLM 批次才能发现。

## 要求

- 使用当前运行态页面做浏览器复查。
- 不点击会触发真实 LLM 生成的最终确认按钮。
- 可创建临时验收系统或查看既有系统，但不能删除用户数据。
- 记录每个关键入口的观察结论：系统/项目、知识库上传、批次页、用例资产、搜索、导出。
- 对照 `docs/acceptance/runbook.md` 检查步骤是否仍准确。
- 产出 `dry-run-report.md`。
- 补充 `review.md`，批判性说明 dry-run 能发现什么、不能证明什么。

## 不做

- 不触发真实 LLM 生成。
- 不替代真实小规模批次验收。
- 不替代首次使用平台的 QA 真人任务演练。
- 不改后端业务逻辑。
- 不改 `src/testcase_generator/**`。

## 验收标准

- `dry-run-report.md` 包含实际访问页面、观察结果和 GO / FOLLOW-UP 结论。
- 若发现 runbook 与页面不一致，更新 runbook 或记录为待修问题。
- `review.md` 明确指出 dry-run 不能证明用例生成质量、模块树质量或真实批次主链路成功。
- 变更不涉及 `src/testcase_generator/**`。
