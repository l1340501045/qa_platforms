# UI 验收前页面动线 dry-run 自审

## 结论

本轮 dry-run 对目标有帮助，但证据边界必须收紧理解：它证明当前运行态页面的入口、文案和基础布局没有明显阻断，不证明真实生成主流程已经成功。

## 可靠证据

- 实际访问了 `/review`、`/systems`、知识库、批次页、`/case-library`、`/search`、`/exports`。
- 知识库页面确认上传前资料类型可见，默认 `PRD`，上传按钮明确“按 PRD 入库”。
- 生成弹窗确认“开始生成”是最终动作，本轮只查看并取消，没有触发生成。
- 1024 宽度关键页面没有页面级横向溢出。
- 批次页当前无浏览器 error / warn。

## 风险

- API 后台脚本在当前执行环境中一度出现后台进程不可持续的问题；后续改用前台会话观察页面。这个属于本地执行环境问题，不应直接归因到 UI。
- 页面 dry-run 使用既有历史数据，不能代表周一新批次数据。
- 批次页“待审阅”状态下 `落库归档` 可用，需要真人演练观察是否造成误操作。
- 用例资产页默认系统为空，需要真实小批次完成后再验证新资产定位。

## 是否偏离目标

没有。此次复查没有改后端业务逻辑，没有触发 LLM 生成，没有改 `src/testcase_generator/**`。它把周一真实验收前可以提前发现的问题继续前移，但仍保留真实批次和真人演练作为合并门槛。
