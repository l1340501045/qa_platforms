# 批次与用例资产质量分流可见性

## Goal

让具备 QA 背景、但第一次使用平台的人，在批次审查页和用例资产页能立即分清：

- 哪些是可进入人工审查的主集候选；
- 哪些是需求待澄清，不应当作可执行测试；
- 哪些是生成/核验发现的待修正或冲突项；
- 当前筛选和资产视图会不会影响“可交付用例”的判断。

本任务只改前端信息架构与展示动线，不改变后端生成 pipeline、批次数据、worker、导出任务语义。

## Requirements

- 批次审查页必须显式展示质量分流摘要，至少包括主集候选、待澄清、待修正、冲突/无依据等现有质量状态。
- 批次审查页必须用业务语言解释 `needs_spec`：这是规格澄清资产，不是可直接执行的测试用例。
- 批次审查页必须用业务语言解释 `to_fix/conflict/ungrounded/undefined`：这是待修正或待人工核对资产，不应混入默认可交付判断。
- 用例资产页的质量筛选文案必须是中文业务语义，不能只显示 `grounded/ungrounded/undefined/conflict` 这类内部枚举。
- 默认视图必须继续优先服务主流程：QA 能从主集候选进入审查、确认、导出，不被质量债务提示阻塞。
- 所有改动必须复用现有 `CaseTreeReview`、`CaseAssetTree`、`CaseAssetTable` 和现有 API 字段；不得复制树构建逻辑，不新增后端契约。
- UI 要适合数据密集后台：不做 landing，不做大面积装饰，不用新色彩体系覆盖现有 Ant Design 风格。
- 不触碰当前脏工作区里与导出中心相关的用户改动。

## Acceptance Criteria

- [ ] 批次页首屏能看到质量分流摘要，并能理解当前批次还有待澄清/待修正资产。
- [ ] 批次页筛选区或提示区能引导 QA 只看主集候选、待澄清、待修正，不需要理解内部枚举。
- [ ] 用例资产页 `verdict` 选项改为中文业务文案，并保留内部值不变。
- [ ] 默认主流程不被阻塞：生成完成批次仍能进入审查、确认、需修改、删除、触发迭代和归档。
- [ ] 1024 宽度下关键审查操作仍可见，不出现页面级横向滚动。
- [ ] `npm run test:case-assets` 通过。
- [ ] `npm run build` 通过。
