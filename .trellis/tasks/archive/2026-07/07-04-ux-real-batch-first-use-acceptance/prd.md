# 真实批次与首次上手验收脚本

## 目标

为 `feat/qa-platform-ux-modernization` 合入 `main` 前补齐最后两类证据：

1. 公司网络下真实 LLM 小批次可以从上传资料走到生成、审查、资产、搜索和导出。
2. 具备 QA 背景、但第一次使用本平台的人，不依赖口头讲解也能理解主流程下一步。

本任务不改代码，不跑真实批次，只产出可执行验收脚本和结果报告模板。

## 背景事实

- 当前 UI/UX 分支已完成 9 个子任务，最近运行态验收通过：API、worker、前端在线，核心页面在 1280 和 1024 宽度下无页面级横向溢出、无控制台错误/告警。
- 当前分支相对 `checkpoint/architecture-migration-pre-ux` 没有 `src/testcase_generator/**` diff，UI/UX 分支没有改生成核心逻辑。
- 当前前端发起生成时使用 `BEST_PRACTICE_GENERATION_CONFIG`：
  - `quality_profile=best_practice_default_2026_07`
  - `existence_merge_enabled=true`
  - `split_cap_enabled=true`
  - `cases_per_tp_cap=4`
  - `p0_quota_enabled=false`
- 当前 `.env` 里关键模型配置为：
  - `LLM_PRIMARY_MODEL=claude-opus-4-6`
  - `LLM_VISION_MODEL=claude-opus-4-6`
  - `LLM_VERIFY_MODEL=deepseek-v4-pro-office`
  - `LLM_CONCURRENCY=8`
- 旧大批次 `6f30e1bd-89ad-4e98-878c-4b48014eb1a4` 已有 `.audit` 审查包，但它只能证明旧数据在新 UI 下可浏览，不能证明当前 HEAD 能稳定跑出新批次。

## 范围

- 写一份真实跑批前置检查清单。
- 写一份小规模真实批次验收脚本。
- 写一份首次使用平台的 QA 任务演练脚本。
- 写一份跑完后交给 Codex 继续审查的结果模板。
- 明确合 `main` 的通过/阻塞标准。

## 不做

- 不改任何后端生成逻辑、worker、LLM 配置或前端代码。
- 不提交真实审查确认、删除或落库到用户生产数据；如果需要 mutation，只在专门验收系统/验收批次里做。
- 不把完整大 PRD 跑批作为 UI/UX 分支合并的唯一硬门槛。完整 PRD 大批次用于生成质量回归和策略评估，小批次用于证明 UI/UX 主链路可用。
- 不把“步骤短”本身作为用例质量失败条件；只判断断言是否可观察、可追溯、可执行。

## 验收要求

### R1 前置环境可证

跑批前必须记录：

- 当前分支和最近提交。
- 工作区是否干净。
- API、worker、frontend 是否在线。
- LLM 模型和并发配置。
- 发起生成的配置是否是当前前端默认配置。

### R2 小规模真实批次可走通

必须使用当前 HEAD 新发起一个真实批次，记录 system id、document id、batch id。

最低通过要求：

- 上传资料时能选择文档类型，上传后不是误落 `other`，除非用户明确选择其他。
- 触发生成后能进入批次页。
- 批次页能展示运行状态、阶段进度、澄清/失败/待审核状态。
- 如果进入待澄清，页面能让 QA 看懂问题并提交澄清。
- 如果进入待审核，页面能展示用例树和列表。
- 生成完成后，用例资产、全局搜索、导出中心能看到或处理该批次相关资产。

### R3 首次上手可理解

邀请一个具备 QA 背景但没用过本平台的人，按脚本完成任务。观察时不能提前讲解页面。

最低通过要求：

- 能从入口页找到项目/系统。
- 能理解先上传资料、再生成批次、再进入审查。
- 能在批次页判断当前状态和下一步。
- 能找到用例资产、搜索和导出。
- 过程中没有需要外部口头解释才能继续的 P0/P1 卡点。

### R4 跑后可审查

跑完真实批次后必须能生成 `.audit/<batch_id>/` 审查包，至少包含：

- `index.json`
- `REPORT.md`
- `prd.md`
- `modules/`
- 如有图片，包含 `image_captions.json`

Codex 后续可基于该审查包继续做用例质量审查。

## 通过 / 阻塞标准

| 级别 | 标准 | 处理 |
|---|---|---|
| P0 阻塞 | 不能上传、不能触发生成、worker 不消费任务、批次页白屏、生成完成后无法审查 | 不合 main，先修 |
| P1 阻塞 | 首次使用者无法判断下一步、文档类型仍误落 `other`、状态含义误导、核心页面数据明显错 | 不合 main，先修 |
| P2 可后续 | 文案不够顺、个别布局拥挤、大 chunk warning、非主链路入口不够优雅 | 可记录后合并或另开任务 |
| 非 UI 阻塞 | LLM 网关不可达、模型超时、生成质量策略问题 | 不归因 UI/UX；转到 infra 或 testcase generator 任务 |

## 交付物

- `acceptance-runbook.md`：周一真实跑批和首次上手验收步骤。
- `post-batch-report-template.md`：跑完后用户回填给 Codex 的信息模板。
- `review.md`：对本验收脚本的批判性自审。

## 完成标准

- 上述 3 个交付物存在且内容可执行。
- 文档明确区分 UI/UX 合并门槛和完整 PRD 生成质量回归。
- 文档没有要求用户理解技术字段；技术检查给出可直接复制的命令。
- 文档没有把大批次耗时任务强行塞进 UI/UX 最小合并门槛。
