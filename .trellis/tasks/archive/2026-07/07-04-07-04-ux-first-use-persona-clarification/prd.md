# 首次使用平台QA验收口径校准

## Goal

把 UI/UX 验收对象明确校准为“具备 QA 背景、但第一次使用本平台的人”。

本任务不是新增功能，也不是改生成逻辑；它只修正验收文档中的口径，避免后续周一真实验收时把“有人讲解平台后能完成”误判成“平台第一次上手也清晰”。

## Confirmed Facts

- 用户已明确纠正：目标不是“新手 QA”，而是“一个 QA 即使没用过这个平台，第一次上手也能清晰知道该干嘛”。
- `docs/acceptance/first-use-observation.md` 已写明对象不是 QA 新人，但部分合并判定文字仍使用“少量提示内完成”，容易放松验收标准。
- 本轮只能改验收口径、观察表和父任务收口文档；不能触碰 `src/testcase_generator/**` 或后端生成链路。

## Requirements

- R1：所有面向周一执行的验收文档必须统一目标用户口径：
  - 具备 QA 背景；
  - 第一次使用本平台；
  - 不需要别人解释平台页面怎么操作；
  - 不是零基础 QA 教学页。
- R2：真人演练的主持人规则必须区分两类提示：
  - 允许的“目标级提示”：只重述当前任务目标，例如“你现在需要找到资料入口”；
  - 不允许作为通过证据的“操作级提示”：告诉按钮、菜单、路径、页面术语定义，例如“点项目/系统”。
- R3：GO / NO-GO 口径必须收紧：
  - 通过不应依赖口头讲解按钮或路径；
  - 如果必须靠操作级提示才能完成上传、生成、审查或导出，应至少记为 P1；
  - 仅有目标级提示且主流程可继续，才可按实际影响评估为 P2 或通过。
- R4：修改只限文档和 Trellis 任务记录，不改前端、不改 API、不改生成核心。

## Out of Scope

- 不重新设计 UI。
- 不启动真实 LLM 批次。
- 不执行真人演练。
- 不调整 testcase generator、模型配置、worker 或导出逻辑。

## Acceptance Criteria

- [x] `docs/acceptance/runbook.md` 的首次使用平台验收和合 main 判定不再把“少量提示内完成”作为宽松通过条件。
- [x] `docs/acceptance/first-use-observation.md` 明确目标用户不是 QA 新人，并明确操作级提示不能算独立完成。
- [x] `docs/acceptance/post-batch-report-template.md` 能记录是否发生平台操作讲解、目标级提示次数和操作级提示次数。
- [x] 父任务合并准备清单 / 集成审查同步该口径。
- [x] 自审记录说明本次没有把目标偏成“新手教程”或“过度苛刻到不允许任何目标级澄清”。
