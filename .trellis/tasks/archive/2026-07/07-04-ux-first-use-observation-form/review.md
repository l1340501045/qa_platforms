# 首次使用平台 QA 演练观察表自审

## 结论

这次补充是必要的。此前 runbook 已经要求做真人首次使用平台演练，但记录方式偏摘要，容易在执行时只留下主观印象。`docs/acceptance/first-use-observation.md` 把任务、观察点、提示规则和 P0/P1/P2 判级标准拆开，能让周一验收结果更可审查。

## 价值

- 明确对象是“具备 QA 背景但首次使用本平台的人”，避免误解成 QA 新人培训。
- 把上传、生成、批次状态、审查、资产、搜索、导出拆成逐步观察项。
- 要求记录提示次数和参与者原话，有助于区分真实 UI 卡点和业务理解问题。
- 对 `落库归档` 这类 dry-run 发现的潜在误解点给了观察入口。

## 风险

- 观察表不能替代真实演练；文档写得再好，也不能证明真人已经完成任务。
- 观察者如果提前解释按钮位置，会污染结果，所以文档强调只给最小提示。
- 判级仍需要工程判断，尤其是 P1 和 P2 的边界；后续回填后需要 Codex 再审。

## 是否偏离目标

没有。它不改产品代码、不触发生成、不碰后端逻辑，只是把剩余合并门槛之一变成可执行证据采集流程。父任务仍不能因为这份观察表而标记完成。
