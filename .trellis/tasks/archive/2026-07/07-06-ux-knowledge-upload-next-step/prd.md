# 知识库上传结果下一步动线

## Goal

让具备 QA 背景但首次使用本平台的人，在知识库上传资料成功后，不需要猜下一步去哪儿：上传结果弹窗里应直接提供“查看详情”和“生成用例”入口，同时保留失败/跳过信息。

这只优化前端动线，不改变文档上传、解析、生成批次、worker 或 testcase generator 后端逻辑。

## Background

当前知识库页已经具备：

- 上传前资料类型选择，默认 `PRD`。
- 选择 `其他` 时的风险提示和确认。
- 文档列表里的“生成用例 / 查看详情 / 标注类型”动作。
- 文件夹树搜索、展开/收起和最大高度限制。

剩余体验缺口在上传完成的一刻：`上传结果`弹窗只列出成功/跳过/失败，用户要关闭弹窗后再回到表格里找刚上传的文档，才能继续查看详情或生成用例。这个断点会让首次使用者误以为“上传结束就是流程结束”，不符合知识库页面“上传资料 -> 生成批次 -> 进入审查”的主流程定位。

## Requirements

1. 上传结果弹窗中，成功上传的每个文档必须展示资料类型标签。
2. 成功上传的每个文档必须提供“查看详情”入口，跳转到当前系统上下文的文档详情页。
3. 成功上传的每个文档必须提供“生成用例”入口，复用现有 `triggerGeneration(documentId)`，成功后跳转批次工作台。
4. “生成用例”必须仍有确认弹窗，避免上传完成后误触发真实生成任务。
5. 弹窗里失败、跳过、图片资产统计等信息必须保留，不得为了加 CTA 牺牲错误可见性。
6. 上传结果弹窗关闭后仍清理 `uploadResult`，保持现有状态生命周期。
7. 不新增后端接口，不改变生成配置，不改 worker / pipeline / testcase generator。

## Acceptance Criteria

- [ ] 成功上传列表每个条目有 `查看详情` 动作。
- [ ] 成功上传列表每个条目有 `生成用例` 动作。
- [ ] 点击 `生成用例` 会先弹出确认；确认后调用现有生成 API 并跳转 `/batches/:batchId`，保留 `from=knowledge&system_id=<systemId>` 上下文。
- [ ] `查看详情` 跳转 `/documents/:documentId?from=knowledge&system_id=<systemId>`。
- [ ] 上传失败和跳过信息仍在弹窗中可见。
- [ ] 改动只涉及前端知识库页面或其必要的前端测试，不涉及 `src/testcase_generator/**`。
- [ ] 前端 lint/build 或相关测试通过。

## Out of Scope

- 不改上传 API 契约。
- 不自动为上传成功的文档发起生成。
- 不做批量生成。
- 不改文档解析、嵌入、知识图谱、用例生成逻辑。
- 不重做知识库页面整体布局。

## Planning Review

本任务是轻量 UI/UX 补口。它直接服务父任务的“主流程不阻塞、首次上手可理解下一步”目标，但范围足够小：只补上传完成后的 CTA，不碰后端生成逻辑，也不改变文档类型、目录树、文档列表现有职责。
