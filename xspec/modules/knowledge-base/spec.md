# SPEC: knowledge-base — 知识库管理与智能检索

> **用途：** 描述知识库模块的需求规格，包含知识导入、组织、关联、检索的完整能力。
> 与实现语言和技术栈无关。
> **裁剪原则：** `(必填)` 必须完成；`(适用时填)` 按触发条件决定。

---

## 1. 概览 (必填)

**交付物：** QA 团队可将 PRD、技术文档、测试规则、历史用例、漏测 Bug 等知识按系统维度导入平台，通过 Agent Skills（动态推理）或 RAG（静态检索）实现智能检索与上下文理解。

**所属项目 / 模块：** qa_platforms / knowledge-base

**上游依赖：**

| 文档类型 | 链接 / 说明 |
|:--- | :--- |
| HLD | 无（首次创建） |
| Research | 无 |
| Data Model | 无（首次创建） |

---

## 2. 背景与目标 (必填)

**问题陈述：** QA 团队的知识分散在飞书文档、本地文件、个人经验中，AI 无法获取完整上下文来生成高质量用例。需要一个统一的知识库，按业务系统维度组织所有测试相关知识，并提供智能检索能力供下游模块（testcase-generator）消费。

**目标：**

- QA 能将 md+图片文件夹一键导入到对应系统的知识库中
- 知识库按「系统 → 文档类型」二级结构组织，QA 可自建文件夹
- 文档间的关联关系可自动建立和检索（需求↔技术文档↔用例↔漏测 Bug）
- 通过 Agent Skills 或 RAG 提供语义级检索，能理解业务上下文和跨系统关系

**成功标志：** 当 testcase-generator 调用检索接口时，能获取到与目标需求相关的技术文档、历史用例、测试规则和漏测 Bug 的完整上下文。

---

## 3. 关键概念 (必填)

- **系统（System）**：业务划分的顶层单元，对应团队实际维护的 4-5 个业务系统，系统间有数据流动和接口调用关系
- **知识文档（Document）**：导入知识库的单个文件单元，含元数据（类型、所属系统、关联关系）
- **文档类型（DocType）**：需求文档 / 技术文档 / 测试规则 / 测试用例 / 漏测 Bug / 可交互原型链接
- **文档关联（Association）**：文档间的业务关联关系（如：需求 A 关联技术文档 B 和用例 C）
- **知识检索上下文（RetrievalContext）**：为下游消费者（如用例生成）组装的多文档聚合上下文

---

## 4. 超出范围 (必填)

- 不负责文档的在线编辑（只做导入和存储）
- 不负责用例生成（由 testcase-generator 模块消费检索结果）
- 不负责用户认证和权限管理（由 platform-api 统一处理）
- 不负责需求文档的版本管理（后续迭代）

---

## 5. 用户场景 (必填)

### 场景 1：导入需求文档文件夹

**目标用户：** QA 工程师

**描述：** QA 从飞书导出 PRD 为 md+图片的文件夹结构后，上传到平台对应系统的知识库中。

**验收行为：**

- **Given** QA 已在平台中创建了「漫剧系统」  
  **When** QA 选择「漫剧系统」并上传一个包含 .md 文件和相对路径图片的文件夹  
  **Then** 系统成功导入所有 .md 文件及其关联图片，保持文件夹层级结构，图片在文档中正确渲染

- **Given** 文件夹中某个 .md 引用了相对路径图片 `./images/flow.png`  
  **When** 导入完成  
  **Then** 该图片与文档正确关联，文档预览时图片可正常显示

---

### 场景 2：建立文档关联

**目标用户：** QA 工程师

**描述：** QA 将需求文档与对应的技术文档、历史用例、漏测 Bug 建立关联关系，使 AI 生成用例时能获取完整上下文。

**验收行为：**

- **Given** 系统中已存在需求文档 A 和技术文档 B  
  **When** QA 在需求文档 A 上操作关联，选择技术文档 B  
  **Then** 两者建立双向关联，任一文档页面均显示关联关系

- **Given** QA 上传漏测 Bug 记录到对应系统  
  **When** 上传完成  
  **Then** 系统支持将漏测 Bug 与对应需求/模块关联

---

### 场景 3：智能检索

**目标用户：** testcase-generator 模块（内部消费者）

**描述：** 用例生成引擎基于目标需求文档，检索所有相关的技术文档、测试规则、历史用例和漏测 Bug。

**验收行为：**

- **Given** 某需求文档已导入并关联了技术文档和历史用例  
  **When** testcase-generator 请求该需求的检索上下文  
  **Then** 返回该需求直接关联的技术文档、同系统的测试规则、历史用例和漏测 Bug，按相关度排序

- **Given** 某需求涉及跨系统交互（如系统 A 调用系统 B 的接口）  
  **When** 请求检索上下文  
  **Then** 检索结果包含系统 B 中相关接口的文档和已知问题

## 6. 边界与异常场景 (必填)

- **EC-01**：上传文件夹中包含非 .md 文件（如 .docx、.pdf）→ 系统提示不支持该格式，跳过该文件，其余文件继续导入
- **EC-02**：.md 文件中引用的图片路径不存在 → 文档正常导入，缺失图片位置显示占位提示"图片缺失: [路径]"
- **EC-03**：上传的文件夹为空或仅包含不支持的文件 → 提示"未找到可导入的 .md 文件"，导入操作取消
- **EC-04**：检索时知识库为空或目标系统下无相关文档 → 返回空结果集并提示"未找到相关知识，建议先导入相关文档"
- **EC-05**：单次上传文件总大小超过系统限制 → 提示具体限制值，建议分批上传

## 7. 功能需求 (必填)

- **FR-01** [MUST] 支持按文件夹结构批量导入 .md 文件及其相对路径图片
- **FR-02** [MUST] 按「系统」维度组织知识库顶层结构，系统下支持自建文件夹
- **FR-03** [MUST] 支持 6 种文档类型的标识：需求文档、技术文档、测试规则、测试用例、漏测 Bug、可交互原型链接
- **FR-04** [MUST] 支持文档间手动建立关联关系（多对多）
- **FR-05** [MUST] 提供智能检索接口，基于目标文档返回相关上下文（含关联文档、同系统规则、历史用例、漏测 Bug）
- **FR-06** [MUST] 检索结果按相关度排序，支持跨系统关联检索
- **FR-07** [SHOULD] 支持在上传时通过文件夹名称自动推断文档类型（如文件夹名含"规则"→测试规则）
- **FR-08** [SHOULD] 可交互原型链接作为文档类型存储，标记为"辅助参考"级别（非最高权威）
- **FR-09** [MAY] 支持基于文档内容自动建议可能的关联关系

---

## 8. 非功能需求 (必填)

- **NFR-01** [性能] 单次文件夹导入（100 个 .md 文件 + 图片）在 60 秒内完成
- **NFR-02** [性能] 检索接口响应时间 < 5 秒（P95）
- **NFR-03** [可靠性] 导入过程中任何单文件失败不影响其余文件的导入，失败文件列表清晰反馈
- **NFR-04** [可靠性] 检索接口在知识库为空时返回结构化空结果，不抛异常

## 9. 验收标准 (必填)

- [ ] **AC-01** *(关联 FR-01)*：上传含 10 个 .md 文件和 5 张图片的文件夹，全部成功导入，图片在文档预览中可见
- [ ] **AC-02** *(关联 FR-02)*：创建「系统 A」后，在其下创建「需求文档」子文件夹，文件夹层级正确展示
- [ ] **AC-03** *(关联 FR-04)*：将需求文档 A 关联技术文档 B，在两个文档页面均可看到关联关系
- [ ] **AC-04** *(关联 FR-05)*：请求需求文档 A 的检索上下文，返回结果包含已关联的技术文档和同系统测试规则
- [ ] **AC-05** *(关联 FR-06)*：需求涉及跨系统接口调用时，检索结果包含目标系统的相关文档
- [ ] **AC-06** *(关联 EC-01)*：上传含 .docx 文件的文件夹，系统跳过 .docx 并提示，.md 文件正常导入
- [ ] **AC-07** *(关联 EC-02)*：.md 中引用的图片路径不存在时，文档正常导入，缺失位置显示占位提示

## 10. Skill 规格（适用时填）

> 本模块的检索能力可能以 Agent Skill 形式提供给 testcase-generator 调用。

| 项 | 值 |
|:--- | :--- |
| **Skill 文件名** | `knowledge-retrieval/SKILL.md` |
| **加载策略** | Lazy-load（按需激活） |
| **激活条件** | testcase-generator 请求生成用例时，自动激活检索 Skill 获取上下文 |
| **依赖的外部工具** | 无 |
| **依赖的环境变量** | 无 |
| **预期输出形态** | 返回结构化的知识上下文（含文档列表、关联关系、相关度评分） |

**与 Agent 工具体系的关系：** 本 Skill 作为 Agent Tool 提供给 testcase-generator 的推理循环调用，用于检索和组装上下文。
